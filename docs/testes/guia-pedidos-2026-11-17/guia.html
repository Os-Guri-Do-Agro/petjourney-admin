Antes de testar

  • Nada subiu ainda. Está tudo commitado no develop local de cada repositório, sem push. Para testar nos ambientes de develop (portal-dev, app de dev, site e CMS), é preciso subir primeiro. No computador, dá para testar o portal pelo npm run dev.
  • Lembrete de vacina (teste E): em 17/11, 21h20, a API de dev ainda não tinha o N42. Confira o primeiro passo do teste E antes.
  • Como foi o preparo: as telas do portal foram abertas com a conta da clínica de QA, lendo a API de dev. Tudo o que grava (ligar módulo, convite, lembrete, editar) foi respondido no próprio navegador, para não mandar mensagem, push nem gastar o teste grátis de ninguém. Por isso o fundo cinza "Não conferido" e as notas "No preparo" dizem o que falta ver de verdade.
  • App: as telas novas não foram abertas no celular; o comportamento foi conferido rodando as funções do app em scripts. É onde mais vale o seu olho.

Como usar

  • Cada passo diz de que lado é: Portal App do responsável Site CMS
  • Faça o que está em negrito e confira o quadro verde Deve aparecer. Os textos entre aspas azuis são os nomes exatos na tela; o que está entre colchetes muda (nome do pet, data).
  • Marque ☐ Passou / ☐ Falhou no alto de cada teste e preencha a folha de resultado no fim.
  • Achou um problema? Mande a letra do teste e o número do passo, o print e a conta. Antes, leia Não é bug e as pendências no fim.
