Como usar

  • Faça os testes na ordem. De D a P o paciente é o mesmo: o Bento, da Júlia. Os prints foram tirados no preparo com a Fubá, da Bruna: no seu teste aparecem Bento e Júlia no lugar. Datas, horas e números mudam.
  • O portal é no computador. O lado do responsável é no app de dev, no celular (o guia do app de 08/11 mostra essas telas). Cada passo diz de que lado é: Portal App do responsável Site CMS
  • No preparo, os passos do app foram feitos pela API de dev, com a conta da responsável, nas mesmas rotas que o app usa.
  • Em cada passo: faça o que está em negrito e confira o quadro verde Deve aparecer. Os textos entre aspas azuis são os nomes exatos dos botões e das telas.
  • Quadro vermelho No preparo: o que aconteceu de errado no preparo. Fundo cinza "não foi conferido no preparo": é o que mais precisa do seu olho.
  • Algumas horas do portal saem no fuso do computador (erro conhecido): com o computador em Cuiabá, some 1 hora nesses lugares.
  • Marque ☐ Passou / ☐ Falhou no alto de cada teste e preencha a folha de resultado no fim.
  • Achou um problema? Mande a letra do teste e o número do passo, o print, a hora e a conta. Antes, leia Erro já conhecido e Não é bug.

Ambientes

  • Portal: o develop do admin contra a API de dev (no preparo, o commit bc519bc servido localmente). A clínica de QA tem os módulos Clínica e Hotel ativos.
  • App de dev: para o lado do responsável. Deixe as notificações ligadas.
  • Site: o petjourney-web contra a API de dev (no preparo, next dev local).
  • CMS: npm run dev no petjourney-cms, com a sua conta de administrador.
